Each workflow in the Arazzo view in Scalar offers an Example input under its inputs: a JSON object made from the inputs schema, with a copy button. It uses the schema's `example`, `examples`, `const`, `default` or `enum` where there is one, otherwise a value of its type (samples for known string formats, the minimum for numbers, the number for a .NET number also read from a string), following `$ref`s into the schema and `components.inputs`. Arrays hold as many items as `minItems` asks for, within `maxItems`, and the example (authored or made up) is checked against the schema: one that does not satisfy it is marked **Needs edits** rather than offered as ready to copy. The check applies a `$ref`'s schema together with the keywords next to it, follows chains of references and pointers into arrays (`#/…/oneOf/0`), honours `true`/`false` schemas, and compares objects regardless of property order. The example is made while the workflow renders, so it is bounded: at most 1000 values, strings of at most 1000 characters and about 100,000 characters of JSON, authored values counted by their size (a schema asking for more gets a shorter example marked **Needs edits**), and a `pattern` is only run when its worst-case backtracking on that value is bounded and small (estimated from its repeats, optional parts and alternatives against the value's length); a repeated group with a choice inside it, such as `(a*)*` or `(a?){30}`, or a backreference is never run.
